# paper-sop-kit · 论文流程脚手架

> 把「八阶段 + 四层门禁 + 人判点」从长篇 SOP 里抽出来，变成一条能跑的状态机。

一篇论文从选题到投稿，最容易失控的不是写不出来，而是**阶段漂移、门禁漏跑、人工断点没人跟**。
本工具用零依赖 Python 生成一个项目骨架与状态文件，让每一步有落点、每次推进有校验。

**Python 3.9+ 标准库，零依赖。**

## 为什么做这个

知识库里有一份《论文生产全流程一体化 SOP v2.0》（PPL 3.0），核心设计是：

- **八阶段** P0 选题 → P1 规范 → P2 文献 → P3 契约 → P4 撰写 → P5 质检 → P6 审查 → P7 投稿；
- **四层门禁** L1 机验 → L2 段级 → L3 整合 → L4 交付；
- **人类守判**：10 个人判点，其中契约锁定（S0）禁止 AI 代理；
- **全程留痕**：任务台账、阶段状态、派发与裁决日志。

原 SOP 依赖本地一套较重的工作台。本工具**不替代那套工作台**，只抽出
「阶段 + 门禁 + 台账」这层最通用的部分，做成任何电脑都能跑的轻量脚手架。

## 安装

```bash
git clone https://github.com/xunshenwu-eng/paper-sop-kit.git
cd paper-sop-kit
python -m paper_sop --help
```

## 用法

```bash
# 生成论文项目骨架
python -m paper_sop init my-thesis

cd my-thesis
python -m paper_sop status              # 当前阶段 / 已完成 / 门禁状态
python -m paper_sop advance P1          # 推进到下一阶段（禁止跳级）
python -m paper_sop gate L1             # 打印并校验某层门禁清单
python -m paper_sop task new "补三篇近五年文献"   # 生成一张任务卡
python -m paper_sop check               # 三审三查交付清单自检
```

> `advance` 只允许顺序推进；跳级会被拒绝并提示当前阶段。
> `check` 不替你判断内容质量，只列出必须人工确认的条目。

## 生成的项目结构

```
my-thesis/
├── sop-state.json        # 阶段 / 门禁 / 时间戳
├── README.md             # 项目说明与阶段路线
├── todo-ledger.md        # 人工断点台账
├── gate-checklist.md     # 四层门禁清单
├── commands.md           # 12 条常用指令速查
├── stages/               # P0–P7 各一个目录
│   ├── P0-选题/
│   └── ...
└── templates/
    └── task-card.md
```

## 阶段与门禁

| 阶段 | 名称 | 关键产物 | 人判点 |
| --- | --- | --- | --- |
| P0 | 选题 | 选题说明、题名—内容对应自检 | ✅ 定题 |
| P1 | 规范 | 格式规范、引用口径 | — |
| P2 | 文献 | 文献池、检索记录 | ✅ 文献取舍 |
| P3 | 契约 | 段落契约锁定 | ✅ **S0 契约锁定（禁止 AI 代理）** |
| P4 | 撰写 | 各章初稿 | ✅ 论证链人写 |
| P5 | 质检 | 机验报告、段级检查 | — |
| P6 | 审查 | 三审三查记录 | ✅ 结论确认 |
| P7 | 投稿 | 定稿、归档清单 | ✅ 最终放行 |

| 门禁 | 检查什么 |
| --- | --- |
| L1 机验 | 格式、链接、引用是否可解析 |
| L2 段级 | 每段是否有契约、是否有来源 |
| L3 整合 | 拼装后结构完整、章节连续 |
| L4 交付 | 三审三查 + 必收准则 + 验收清单 |

## 边界

- **不写论文、不调模型、不联网**。只管流程状态与文件骨架。
- **不搬原 SOP 全文**。29 条指令是原工作台专用，本项目只保留 12 条通用自然语言指令模板。
- `check` 输出的是待人工确认清单，不是质量评分；幻觉、论证质量、导师反馈仍需人判。
- 状态文件是纯 JSON，可直接手工编辑；工具不会锁文件。
